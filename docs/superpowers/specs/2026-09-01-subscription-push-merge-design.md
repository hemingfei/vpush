# 订阅与推送合并设计

日期：2026-09-01
状态：已确认

## 目标

把网页端的“组合订阅”“我的订阅”“推送设置”收成一个顶层入口，减少重复导航，并按用户任务明确分工：订阅广场负责发现内容，“订阅与推送”负责维护已订内容和配置送达方式。

本次是网页信息架构调整。后端已经将大 V 和雪球组合存入同一套 `subscriptions` 关系，无需迁移数据或增加 API。

## 已确认决策

- 顶层入口由“推送设置”改名为“订阅与推送”。
- 在现有设置页增加“订阅管理”标签，并作为进入页面后的默认标签。
- 页内保留五个标签：订阅管理、推送设置、渠道绑定、AI 摘要、账号设置。
- 桌面侧栏和手机底栏移除独立的“组合订阅”和“我的订阅”。
- 订阅广场继续负责发现全部内容；雪球组合通过广场现有“组合”平台筛选发现。
- “订阅管理”只管理已订阅项目，不混入未订阅组合目录。
- 本次只改网页端，小程序保持现状。

## 范围

包含：

- 网页桌面侧栏、手机底栏和页面标题中的入口名称与导航项。
- 设置页新增“订阅管理”标签，并复用现有“我的订阅”列表能力。
- 大 V 与雪球组合在同一列表中展示，通过现有平台筛选区分。
- 保留帖子/回复订阅类型、特别关注、次要订阅和退订操作。
- 兼容 `/mysubs` 与 `/combinations` 旧路径。
- 更新与这些入口相关的网页文案、文档和前端契约测试。

不包含：

- 不修改数据库结构、订阅 API、推送调度、抓取逻辑或通知格式。
- 不修改小程序页面、导航或文案。
- 不增加搜索、批量操作、自定义订阅分组或第二套“大 V / 组合”分类标签。
- 不移动“动态图片”设置；它继续位于“推送设置”标签。
- 不新增通用组件或第三方依赖。

## 信息架构

网页顶层导航中，订阅相关入口为：

1. **最新动态**：阅读已订内容。
2. **研报库**：阅读研报内容。
3. **订阅广场**：发现并订阅大 V、雪球组合及其他平台内容。
4. **订阅与推送**：维护已订内容并配置推送。

“订阅与推送”页包含：

1. **订阅管理**：已订项目、平台筛选、特别关注筛选和单项订阅操作；默认打开。
2. **推送设置**：总开关、每日精选、X 翻译、免打扰、关键词和动态图片。
3. **渠道绑定**：渠道状态、接收渠道选择和绑定流程。
4. **AI 摘要**：用户自己的 OpenAI 兼容模型配置。
5. **账号设置**：密码与机器人账号同步。

## 订阅管理

“订阅管理”迁移现有“我的订阅”的行为，不创建另一套订阅列表：

- 请求仍使用 `GET /api/my/subscriptions`。
- 列表同时容纳普通大 V 和 `combination` 平台项目。
- 桌面使用现有带字平台筛选；手机继续使用一行等宽图标角标。
- 特别关注关闭时，特别关注项目仍按现有规则优先排序。
- 列表继续按现有分类分组，未分类放在最后。
- 雪球大 V 保留帖子/回复开关；组合不显示无意义的帖子/回复选项。
- 每项保留特别关注、次要订阅和退订。
- 空态提供“去订阅广场”操作，不在本页嵌入发现目录。

“动态图片”虽然也是单项订阅属性，但本次保持在“推送设置”，避免扩大重组范围。

## 路由兼容

- 访问 `/settings` 时默认显示“订阅管理”。
- 访问旧路径 `/mysubs` 时，使用替换导航进入 `/settings` 并打开“订阅管理”，避免留下重复历史记录。
- 访问旧路径 `/combinations` 时，使用替换导航进入 `/home`，并将订阅广场平台筛选设为 `combination`。
- 新导航不再生成 `/mysubs` 或 `/combinations` 链接。
- 浏览器前进、后退和快速切换页面时继续使用现有路由序号，避免过期请求写入当前页面。

## 状态与错误

- 加载状态沿用设置页与订阅列表现有反馈方式。
- 无订阅时显示明确空态和“去订阅广场”操作。
- 首次加载失败时只在“订阅管理”标签内显示错误，不影响其他设置标签切换。
- 帖子/回复至少保留一种；全不选继续提示用户通过退订完成关闭。
- 特别关注、次要订阅和订阅类型保存失败时恢复服务端状态。
- 退订继续二次确认；成功后刷新当前订阅列表和订阅计数。

## 响应式与视觉

- 继续沿用 V Push 的值班台视觉体系：灰底、白面、1px 描边、Duty Blue 只表示选中和主操作。
- 五个页内标签在桌面保持单行；手机允许横向滚动，当前“订阅管理”标签首次进入时必须可见。
- 手机平台筛选继续遵守现有一行等宽图标角标约定，不改为文字胶囊或横滑平台 chip。
- 列表卡片、控件高度、深色主题和键盘焦点沿用现有组件规则。
- 移除两个底栏项目后，不用新增入口填满空位；剩余项目稳定等分。

## 验证

- 前端契约测试锁定：导航只出现“订阅与推送”，设置标签包含“订阅管理”，默认标签正确。
- 路由测试锁定：`/mysubs` 进入订阅管理，`/combinations` 进入广场组合筛选。
- 现有订阅 API 测试继续覆盖大 V 与组合共用订阅关系、订阅类型、特别关注、次要和退订。
- 运行 JavaScript 语法检查和完整 `tests/test_frontend_interactions.py`。
- 在桌面与手机视口检查浅色和深色：标签可达、文字不溢出、底栏无空洞或错位、平台角标保持一行。
- 检查旧链接、浏览器前进/后退、快速切换标签及加载失败状态。
