# VPUSH 订阅与财经新闻统一实施计划

> 这是两份已确认规格的执行总控。详细实现步骤仍以各自计划为准，所有前端写入按本文件的顺序串行完成。

## 目标

把网页端订阅管理和财经新闻聚合在同一条发布流水线中完成，同时保持产品边界清楚：

- 动态 = 大 V 动态 + 华尔街见闻实时快讯
- 财经新闻 = 用户选择媒体后的长文阅读
- 研报库 = 研究文档
- 订阅与推送 = 已订内容维护和送达配置

华尔街见闻快讯保留在动态原位，不迁移、不入库、不进入财经新闻来源设置，也不与财经长文混排。

## 执行顺序

### 阶段一：合并订阅与推送

按订阅详细计划依次执行 Task 1-4：

1. 合并桌面侧栏和手机底栏入口，旧 `/mysubs`、`/combinations` 路由保留兼容重定向。
2. 在设置页增加默认打开的“订阅管理”标签，复用现有订阅列表和加载逻辑。
3. 更新 README、DOCKERHUB 和用户指南中的网页入口说明，小程序文案不改。
4. 运行 JavaScript 检查、前端契约测试、桌面/手机浅色/深色主题验收和完整回归。

本阶段只允许修改订阅计划列出的网页文件和文档；后端、数据库、小程序保持不变。提交后应得到：

- 桌面：最新动态、研报库、订阅广场、订阅与推送
- 手机：动态、广场、订阅与推送，以及管理员现有“更多”入口
- 设置默认标签：订阅管理
- `app.js?v=371`、`dav-shell-v240`
- `APP_VERSION=1.12.125`、`style.css?v=261`

### 阶段二：财经新闻后端能力

在阶段一提交之后，按财经新闻详细计划执行 Task 1-7：

1. 扩展固定 IP 的安全请求器，加入默认端口和解压后响应体限制。
2. 增加新闻表、内置媒体/Feed、用户默认选择和迁移。
3. 增加新闻持久化查询、归档、恢复、清理和 seen 锚点。
4. 增加 RSS/Atom 解析、URL 归一化、Bleach 清洗和图片索引。
5. 增加共享 `NewsService`、条件抓取、Feed 锁和 Scheduler 接入。
6. 增加登录用户新闻来源、列表、全文、图片和 seen API。
7. 增加管理员媒体/Feed/设置/刷新 API 及操作日志。

每项先写失败测试，确认红灯后写最小实现，再运行该项及相关回归测试。财经新闻服务不得接入任何通知、摘要、推送或现有 WSCN 链路。

### 阶段三：财经新闻网页能力

继续执行财经新闻详细计划 Task 8-9：

1. 增加管理员媒体主从 Feed 管理界面。
2. 增加独立“财经新闻”桌面/手机导航入口、来源选择、列表、全文阅读和安全图片 Blob 加载。
3. 财经新闻直接进入文章列表，不设置“快讯 / 财经新闻”页签。
4. `动态`页面和其中的 WSCN 快讯渲染、15 秒轮询、缓存、筛选、无限滚动和滚动位置不得改动。
5. 将财经新闻相关产品/设计文档更新为与订阅合并后的最终导航。

本阶段完成后最终导航为：

- 桌面：最新动态、财经新闻、研报库、订阅广场、订阅与推送
- 手机：动态、财经新闻、广场、订阅与推送，以及管理员现有“更多”入口

### 阶段四：统一发布与验收

执行财经新闻详细计划 Task 10，并把版本基线按阶段一结果校准：

- `APP_VERSION`: `1.12.125` -> `1.12.126`
- `style.css?v=261` -> `262`
- `app.js?v=371` -> `372`
- `dav-shell-v240` -> `dav-shell-v241`

如果阶段一或并行发布已使用更高版本，逐项只递增一次，不覆盖更新值。运行新闻 focused suites、订阅前端套件、完整 `pytest -q`、真实 Feed 本地 smoke test 和 1440px/320px Playwright 验收。

## 文件冲突规则

- `app/static/app.js`：阶段一先改导航/设置；阶段三在其最终内容上追加财经新闻，不允许从旧基线重新套补丁。
- `app/static/index.html`、`app/static/sw.js`：阶段一只递增 app 查询和 shell key；阶段四再递增一次，避免复用版本值。
- `app/static/style.css`：订阅阶段默认不改；财经新闻阶段统一加入新闻界面样式并在阶段四递增样式查询。
- `PRODUCT.md`、`DESIGN.md`：财经新闻阶段依据订阅合并后的导航更新，不能恢复已删除的独立“我的订阅”和“组合订阅”入口。
- `README.md`、`DOCKERHUB.md`、`docs/用户指南.md`：只由订阅阶段更新；财经新闻阶段不重写订阅说明。
- 每个提交前只暂存本阶段计划列出的文件，保留工作区已有的无关修改和未跟踪文件。

## 阶段门禁

- [ ] 订阅阶段 focused tests、完整前端测试和浏览器验收通过后，才能开始财经新闻后端。
- [ ] 财经新闻 Task 1-7 的后端测试通过后，才能开始 UI。
- [ ] 财经新闻列表/管理 UI 测试通过后，才能递增最终版本和做真实 Feed 验收。
- [ ] 最终提交前确认 WSCN 仍在动态平台条，未出现资讯中心页签或快讯迁移代码。
