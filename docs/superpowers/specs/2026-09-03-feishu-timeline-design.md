# 飞书时间线阅读体验重构

- 日期：2026-09-03
- 状态：设计已确认
- 范围：研报库中的飞书时间线模式

## 目标

修复飞书时间线日期、时间轨道与正文的水平错位；删除无用的顶部文档提示和不可用媒体占位；保持正文、表格、可用图片、附件入口、发言人/回复关系和原始时间信息完整；降低首屏加载和渲染成本。

## 已确认的用户选择

- 视觉结构：B「信息密度优先」
- 首屏范围：最新 7 个自然日
- 加载方案：服务端窗口 + 稳定游标

## 设计

### 1. 时间线布局

时间线使用固定的时间轨道和内容轨道：

- 左侧时间轨道固定宽度，时间右对齐。
- 有明确单一发言人时，在时间轨道显示紧凑作者名。
- 多发言人或回复关系继续在正文块中显示完整 speaker/reply_to 信息。
- 日期标题、时间、节点、连接线和正文内容共享同一组轨道尺寸，不再使用彼此独立的硬编码偏移量。
- 内容列占据剩余空间；正文保留当前的换行、长文本溢出、表格横向滚动和附件操作。
- 桌面端保留日期导航；移动端隐藏侧栏，使用现有日期选择器。
- 所有按钮和选择控件维持现有可访问名称及至少 44px 的移动端触控高度。

### 2. 内容边界

`renderFeishuTimelineView` 不再输出 `feishu-timeline-notice` 卡片或“文档提示”标题。

时间戳之前的内容仍由 API 以 `notices` 字段保留，但不在研报库时间线 UI 渲染为前置公告；这包括文档标题回显和“拼团有风险……”等公告。时间戳之后的真实正文、表格和附件必须继续输出。

- `asset.unavailable` 的“作者未开放下载，仅飞书内可看”提示。
- 可用图片请求失败后留下的空图片链接壳。

可用图片、文件附件按钮、表格内容、发言人和回复关系都必须继续输出。文档实际正文中的“收起”等文本不能按 UI 文案误删。

### 3. 分段加载

现有完整接口保持兼容；新时间线客户端使用可选分页参数：

```text
GET /api/ima-documents/timeline/all
  ?order=latest|original
  &group=<optional-readable-group-id>
  &window_days=7
  &before=<opaque-cursor>
```

约定：

- 未传 `window_days` 时保留旧的完整返回行为，避免影响旧客户端和文档模式。
- 时间线模式首次请求 `order=latest&window_days=7`；来源已选中时传 `group`，减少无关来源读取。
- 服务端按 `(timestamp, id)` 的稳定排序生成不透明游标。首次页以最新记录为上界，返回最近 7 个自然日；后续页以 `before` 为上界，继续返回更早的 7 日窗口。
- 同一时间戳用 `id` 做并列排序，页边界使用严格游标比较，确保不重复、不遗漏。
- 响应继续返回授权后的 `sources` 和当前页 `entries`，并增加：

```json
{
  "has_more": true,
  "next_cursor": "..."
}
```

  没有下一页时 `has_more` 为 `false`、`next_cursor` 为空。
- `notices` 可继续由 API 返回以保持兼容，但前端不再渲染前置公告。
- `order=original` 的文档模式继续使用完整原始顺序，不在本次扩大为另一套分页行为。

前端状态保存当前页集合、游标、是否还有更多和请求状态。成功的“加载更早”把条目追加到当前列表并按 id 去重；排序或来源切换清空旧页并从第一页重新请求。图片只在已加载页中请求，失败移除完整链接元素。

### 4. 异常与刷新

- 首屏使用现有加载状态。
- 加载更多期间按钮禁用并显示进行中状态。
- 分页失败不清空已有内容，在操作位置显示可重试错误。
- 没有更多内容时不再显示可点击操作。
- 保留现有路由序列号、阅读器序列号和 60 秒更新检查，防止旧请求覆盖当前页面。
- 新内容提示仍由用户点击后重新载入第一页，不自动打断阅读位置。

## 非目标

- 不改变飞书同步、时间线归档格式、权限判断或媒体下载接口。
- 不改变非飞书研报列表和阅读器。
- 不新增 UI 框架或图片处理依赖。
- 不把真实正文、表格或附件因为“简化 UI”而删除。

## 验收与测试

### API

- 首次请求只返回最新 7 个自然日。
- 游标请求返回更早内容，页边界无重复、无遗漏。
- 同一分钟多条记录按 id 稳定分页。
- 多来源排序、来源过滤和权限过滤正确。
- 未传窗口参数的旧接口行为保持不变。

### 前端

- 时间、节点、作者、正文在桌面和移动端使用同一轨道规则对齐。
- 不生成顶部文档提示标题/卡片。
- 不生成不可用媒体占位，不留下失败图片空链接。
- 正文、表格、可用图片、附件下载、speaker/reply 继续可用。
- 加载更多、无更多、失败重试、排序切换、来源切换和日期跳转均有契约测试。

### 性能观测

用现有完整接口作为基线，对比首屏接口的响应字节数、首屏条目数、首屏 DOM 节点数和图片请求数；验证首屏不再等待全量历史内容和全量媒体请求。

## 实施顺序

1. 先为 API 窗口、游标和边界行为补失败测试。
2. 实现最小服务端分页，并运行后端相关测试。
3. 为前端分页状态和 B 结构补失败测试。
4. 实现渲染、资源清理、加载更多和 CSS 轨道变量。
5. 运行前端/后端回归测试、静态检查和视觉验证，最后运行一次 Impeccable detector。
