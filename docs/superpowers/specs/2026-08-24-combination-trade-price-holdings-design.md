# 组合调仓卡片补充成交价与现有持仓

## 目标

组合调仓通知在已有收益统计和仓位变更的基础上：

- 每笔调仓明细在对应仓位变化下显示雪球接口提供的成交价格。
- 在调仓明细之后显示本次抓取到的调仓后现有持仓。
- 价格或持仓快照缺失时隐藏对应内容，不用估算值，也不阻断调仓通知。

## 方案

复用 `Post.detail` 现有结构，不新增 API 或数据库表：

```json
{
  "actions": [
    {
      "type": "新建",
      "stock": "同花顺",
      "symbol": "SZ300033",
      "prev": "0.0%",
      "target": "20.0%",
      "price": "18.42"
    }
  ],
  "holdings": [
    {"name": "同花顺", "symbol": "SZ300033", "weight": 20.0},
    {"name": "现金", "symbol": "CASH", "weight": 31.4}
  ],
  "cash": "31.4%"
}
```

后端从 `rebalancing_histories` 兼容读取常见价格字段（优先 `price`，再尝试 `stock_price` / `trade_price`）；只有能解析为数值时才格式化为价格字符串。现有持仓复用 `current.json` 已写入的 holdings 快照，沿用其 TTL 和失败容错。

## 展示

各渠道统一采用以下顺序：收益统计、调仓明细、现金、现有持仓、时间/原文入口。

- 飞书：每笔调仓块在仓位行下增加 `成交价`；后面增加独立的“现有持仓”块，每只持仓一行，显示名称、代码和权重。
- Telegram / 企业微信：沿用当前文本排版，在对应仓位行增加成交价，并追加“现有持仓”列表。

## 降级与兼容

- 历史帖子没有新字段时按旧格式渲染。
- 没有成交价时不显示“成交价”标签。
- 没有持仓快照或快照为空时不显示“现有持仓”区块。
- 现有现金字段继续使用 `cash_value / 净值` 计算结果，不使用调仓历史中的伪 cash。

## 验证

- 扩展组合抓取测试，覆盖成交价字段透传、持仓快照透传和无价格字段兼容。
- 扩展 Telegram、企业微信和飞书组合格式测试，确认新字段显示且旧 detail 不报错。
- 运行相关 pytest；再运行小程序/前端静态测试，确认无无关回归。
