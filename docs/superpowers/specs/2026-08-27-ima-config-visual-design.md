# IMA 配置区块视觉统一设计

日期：2026-08-27
状态：已确认

## 目标

统一「数据源 → 抓取设置」里的「IMA 文档采集」和「Cookie 管理」里的「ima 凭证」两个区块，使它们遵循现有 `DESIGN.md` 的“值班台”规范，并与同页其他配置区块保持一致。

## 范围

包含：

- 两个 IMA 区块的 HTML 层级、布局、间距、字体、控件尺寸和响应式样式。
- 复用现有 `section-panel`、`cfg-group`、`cfg-fields`、`cfg-foot`、`form-control`、`btn-normal`、`btn-ghost` 和设计 token。
- IMA UID、知识库 ID、根文件夹 ID、Refresh Token、Cookie、OpenAPI Client ID/API Key 等原始标识和凭证使用等宽字体。
- 删除 IMA 凭证区块的行内布局样式，改用作用域 CSS。

不包含：

- 不修改任何 API、凭证读取/保存、采集、同步、校验和错误处理逻辑。
- 不修改现有字段 ID、按钮事件、接口地址或文案含义。
- 不新增通用表单组件或第三方依赖。
- 不改变其他数据源、Cookie 区块或知识库权限页面的视觉行为。

## 设计

### IMA 文档采集

保留独立的 `section-panel` 和现有标题/说明。内容按现有配置页的结构整理：

1. 连接与同步字段使用 `cfg-group`，桌面两列、窄屏单列；标签使用项目 label 角色，输入使用正文尺寸和现有 42px 控件。
2. 每个 IMA 群组使用独立的 `cfg-group` 行，字段网格、启用开关和移除操作在同一组内，避免多个群组字段连成一块无边界区域。
3. 状态与“保存采集配置 / 立即同步”使用 `cfg-foot` 节奏，桌面左右分布，手机纵向或等宽铺开，触控高度至少 44px。

### ima 凭证

保留 Cookie 管理中的独立 `section-panel` 和运行状态说明。凭证字段改为作用域表单布局：

1. 网页 Cookie 单独占满一行，继续使用 `.cookie-paste` 等宽字体。
2. OpenAPI Client ID 和 API Key 使用同一字段网格，标签、输入和间距与其他 Cookie 表单一致；输入值使用等宽字体。
3. 按钮使用现有标准主按钮/幽灵按钮，不再用行内 `margin-top` 或 `display` 控制布局。
4. 桌面按可用宽度分列，手机单列；所有输入和按钮满足现有 42/44px 触控规范。

## 响应式和主题

- 使用 token 间距，不引入任意负边距或新的颜色体系。
- 浅色/深色只通过现有 CSS 变量切换，保持 1px 描边、无休息态阴影和 Duty Blue 稀缺规则。
- 长 ID、Token 和错误提示允许换行或横向滚动，不撑破面板。
- 保持 DOM 顺序与视觉顺序一致，键盘焦点顺序不变。

## 验证

- 更新前端契约测试，确认两个区块仍在对应 tab，字段 ID 和事件保持不变。
- 运行前端交互测试。
- 用项目已有页面启动方式检查抓取设置和 Cookie 管理两个 tab 的桌面、窄屏布局。
- 运行 Impeccable 的 layout/type 机械检测，确认没有未解释的布局、字体违规。
