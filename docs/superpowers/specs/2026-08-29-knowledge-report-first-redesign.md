# 知识库研报优先重构

> 状态：已确认  
> 日期：2026-08-29  
> 取代：`2026-08-29-knowledge-desk-tighten-design.md` 中的两栏研究桌方案

## 1. 目标

知识库的首要任务是：用户输入股票、公司、行业、主题或机构后，最快找到最新且相关的研报，并能立即阅读 PDF。

本轮推倒现有知识库 UI 与交互结构，但继续复用现有文档、搜索、分页和 PDF 接口。后端存储与同步流程不重写。

桌面端采用 **Operate + Read** 模式：研报流负责查找，独立阅读页负责阅读。手机端继续禁用知识库，不设计移动 PDF 阅读器。

## 2. 核心原则

1. **研报是唯一一级对象。** 公司研报、行业研报、宏观报告和主题报告进入同一条研报流。
2. **公司退为检索维度。** 股票代码与公司名只作为搜索条件、筛选范围和文档元信息，不占据独立首页板块。
3. **无代码文档是正常研报。** 不显示“未知股票”“独立研报”或“未归类”这类降级标签。
4. **查找与阅读分离。** 结果页保持高密度，PDF 使用独立阅读页，不再固定挤在侧栏旁。
5. **返回必须保留上下文。** 返回结果页后恢复关键词、筛选、分页、滚动位置和选中项。
6. **Duty Console 不变。** 灰底、白面、1px 描边；Duty Blue 只标选中、主操作和焦点。

## 3. 信息架构

### 3.1 研报流

知识库入口默认展示“最新研报”，按有效日期倒序排列；无日期文档显示 `—` 并排在有日期文档之后。

页面结构：

- 紧凑页头：知识库名称、总数、最近更新时间、刷新。
- 全局搜索：搜索标题、股票代码、公司、行业、主题或机构。
- 条件区：只展示现有数据明确支持的筛选条件。
- 研报列表：日期、标题与次级元信息、机构、可选类型。
- 明确的“加载更多”按钮，不做自动无限滚动。

研报列表保持单一视觉层级。公司研报不获得更大的卡片、头像或品牌区。

### 3.2 公司范围

当搜索词明确命中公司或股票代码时，在搜索框下显示一条轻量范围提示，例如：

`当前范围：蒙牛乳业 2319.HK · 清除`

这不是公司卡片。用户仍然看到统一研报列表，只是结果限定到该公司。点击研报元信息中的公司或代码，也进入同一范围。

### 3.3 分类与标签

类型、行业和主题只使用服务端或 manifest 中已有的明确元数据。不得用标题关键词在前端猜测“宏观”“行业”“主题”。

- 有明确类型/标签：显示筛选项和紧凑元信息。
- 没有明确类型/标签：文档仍正常进入“全部”列表，不显示空标签。
- 一篇报告可包含多个标签；股票代码是可选元信息。

## 4. 研报列表

每行高度约 48–52px，结构稳定，不因内容变化跳动：

- 日期：短格式，如 `8/29`；未知为 `—`。
- 标题：单行截断，是最强视觉信息。
- 次级元信息：机构、行业/主题、股票代码、页数中存在的部分。
- 类型：仅在有可靠数据时显示，弱化处理。

选中行只使用淡蓝背景与蓝色标题，尺寸和字重不跳变。列表支持：

- `↑` / `↓` 或 `J` / `K` 移动选中。
- `Enter` 打开阅读页。
- `Esc` 清除当前公司范围或筛选。
- 鼠标点击打开文档。

## 5. 搜索与结果

搜索输入采用短防抖，结果按“相关性优先、日期次序”返回。默认空查询保持最新流。

搜索状态包括：

- 关键词。
- 公司范围。
- 显式筛选。
- 已加载页数。
- 当前选中研报。
- 列表滚动位置。

打开阅读页时保存这份状态。浏览器返回或阅读页“返回 N 条结果”必须恢复原状态，不重新跳到最新流首屏。

没有结果时保留搜索词和筛选，并显示：

- `没有找到相关研报`
- `换个公司、代码或主题试试`
- `清除筛选`

不使用插画、大卡片或推荐内容填充空态。

## 6. 独立阅读页

阅读页由四部分组成：

1. **紧凑顶栏**：返回结果、页内搜索入口、唯一的应用级下载按钮。
2. **文档信息区**：标题、机构、日期、可选股票/公司元信息。
3. **摘要区**：默认展开，可折叠；本次阅读期间保持折叠状态。
4. **PDF 区**：继续使用浏览器原生 PDF 查看器，保留其黑色工具栏、缩略图和边缘。

下载按钮固定在阅读页顶栏，不放进摘要正文。浏览器 PDF 查看器自带的下载属于查看器原生能力，不额外遮挡或裁切。

阅读页底部提供同一结果集中的上一份/下一份研报。其顺序固定为进入阅读页时的结果顺序，不因后台刷新而变化。

若当前结果只有一份，则隐藏上一份/下一份区域。

## 7. 状态与错误

### 首次加载

使用与真实列表相同尺寸的 5–6 行骨架，避免布局跳动。

### 后台刷新

保留旧列表。刷新失败时在列表上方显示行内错误与“重试”，旧内容仍可打开。

### 首次请求失败

显示简洁整页错误、原因和重试操作；不伪装为空列表。

### PDF 预览失败

保留标题、元信息与摘要。PDF 区只显示一行失败说明；下载仍只走顶栏入口，不在失败区复制第二个按钮。

### 日期或元信息缺失

保留文档。日期显示 `—`；缺少公司、机构、标签时直接省略对应字段，不显示占位文案。

## 8. 布局与视觉

- 知识库内容使用完整主列，不保留固定文档侧栏。
- 列表以扫描效率为主，不使用重复卡片。
- 标题使用 13–15px，页名与阅读标题使用 17px 左右；不用展示型大标题。
- 控件沿用 V Push 现有 token 与原生图标体系。
- Duty Blue 面积保持在约 10% 以下。
- 表面平面化，以 Paper / Surface 色差和 1px 线分层，不增加常驻阴影。
- 1280px 与 1440px 桌面宽度均应完整显示搜索、列表和阅读操作。
- 手机端继续显示现有桌面端提示，底栏不增加知识库入口。

## 9. 数据与实现边界

本轮复用现有 IMA 文档 API 与 PDF API。前端负责：

- 研报流渲染。
- 搜索与筛选状态。
- 阅读路由及返回状态。
- 同一结果集的上一份/下一份。
- 加载、空态和错误态。

只有当现有 API 已返回可靠字段时才展示机构、类型、主题或股票范围。不得为完成视觉稿而加入脆弱的前端文本分类器。

若未来需要可靠的跨年日期、文档类型或多公司关联，应单独扩展 manifest/API；不在本轮 UI 重构中推断。

## 10. 参考与取舍

参考成熟项目的交互思想，但不直接复制布局：

- **Zotero**：借鉴从检索集合进入阅读、再返回集合的连续工作流；不采用固定三栏。
- **Paperless-ngx**：借鉴文档优先的筛选与元信息模型；不采用档案管理式批量操作首页。
- **VENN 等研究工作台**：借鉴独立 PDF 阅读上下文；明确不加入 AI、知识图谱、笔记或画布。

## 11. 非目标

- PDF.js 或自定义 PDF 工具栏。
- AI 摘要、RAG、知识图谱、笔记和标注。
- 三栏布局、永久公司侧栏或公司卡片首页。
- 手机 PDF 阅读器。
- 服务端文档去重、日期模型重构或同步流程改造。
- 批量管理、批量标签和文件管理器式操作。

## 12. 验收

### 行为

- 默认进入最新研报流。
- 搜索公司、代码、标题和已有标签可得到正确结果。
- 无股票代码的报告与公司研报同权展示。
- 阅读后返回可恢复完整结果状态与滚动位置。
- 上一份/下一份严格沿用进入阅读页时的结果顺序。
- PDF 失败时文档信息仍可读，下载入口不重复。
- 无日期、无标签、无机构的文档不会被丢弃。

### 测试

- 静态/单元测试覆盖列表渲染、可选元信息、省略规则和排序。
- 交互测试覆盖搜索、公司范围、加载更多、阅读返回、上一份/下一份和失败态。
- 浏览器截图覆盖 1280×800 与 1440×900 的默认流、搜索结果、阅读页、无结果和 PDF 失败。
- `node --check app/static/app.js` 通过。
- 现有知识库手机禁用行为保持通过。
