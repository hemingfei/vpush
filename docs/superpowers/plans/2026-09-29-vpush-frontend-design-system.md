# V Push Frontend Design System Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Unify V Push's frontend design tokens and shared visual states in the existing A direction across the workbench, admin UI, and mobile layouts.

**Architecture:** Keep the existing vanilla JS/CSS app. Treat `app/static/vendor/design-tokens.css` as the sole token source and `app/static/style.css` as the shared component styling layer; use existing HTML/JS behavior and responsive breakpoints. Regenerate fingerprinted references with `scripts/bump_assets.py` after source edits.

**Tech Stack:** CSS custom properties, vanilla JavaScript, Python asset-sync script, pytest, existing browser-based visual companion.

---

## File Map

- Modify `app/static/vendor/design-tokens.css`: semantic light/dark tokens, control sizes, radii, spacing, focus and elevation vocabulary.
- Modify `app/static/style.css`: migrate shared and page styles to tokens; preserve behavior and responsive layout.
- Modify `DESIGN.md` only if token/component values or usage rules change from the documented system.
- Generated by `python scripts/bump_assets.py --sync`: `app/static/index.html` and `app/static/sw.js` fingerprint references. Do not hand-edit their generated hashes.
- Existing regression coverage: `tests/test_frontend_interactions.py`, `tests/test_frontend_runtime.py`, `tests/test_frontend_pwa.py`, `tests/test_static_cache.py`, and `tests/test_asset_versions.py`.
