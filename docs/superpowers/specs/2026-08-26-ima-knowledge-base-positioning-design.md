# IMA 文档改为知识库定位

- 日期：2026-08-26
- 状态：待用户复核
- 依赖：
  - `docs/superpowers/specs/2026-08-26-ima-document-center-multi-group-design.md`（群组注册表、自动发现、按库归档）
  - `docs/superpowers/specs/2026-08-26-ima-per-group-interval-design.md`（每库采集间隔；本规格不改调度）
- 覆盖多群组规格中的这些结论：
  - 「普通已认证用户可读取全部已启用群组的归档文档」
  - 用户入口仍叫「IMA 文档」
  - `enabled` 同时控制前台可见

## 1. 目标与范围

### 目标

1. 用户侧入口和信息架构改成「知识库」：按 ima 已订阅库浏览，不再把模块当成日期堆叠的 PDF 仓库。
2. 目录与当前 ima 账号的已订阅库 1:1 镜像（自动发现），不做自有库产品面。
3. 列表先展示标题、摘要、封面；本地已经采到的 PDF 仍可打开。
4. 普通用户必须先被管理员授权，再自己订阅，才能进入某个库。
5. 知识库条目不进时间线、不推送、不写入 `posts`。
6. 每条文档自动打标，复用现有词表（行业/话题）和股票名表，主要标股票名和行业名。

### 范围

- 侧栏、时间线入口文案、前端路由从「IMA 文档」改为「知识库」。
- 用户页：已订阅 / 可订阅、按库看条目、元数据优先的列表与阅读。
- 两张新表：授权（ACL）、用户订阅。
- 现有 `/api/ima-documents*` 加上权限过滤；新增订阅与 ACL 接口。
- 列表记录补摘要、封面（采集拉列表时若有就写入），不改 PDF/TXT 文件格式和下载。
- 条目自动打标：复用 `app/tagging.py` 与后台词表/股票名表；库内按标签筛选。存量文档回填一次。

### 不在本期

- 改采集协议、加密下载、PDF/TXT 落盘路径或文件名规则。
- 每库间隔、调度心跳、全局间隔下线（归按群间隔规格）。
- 把知识库塞进 `kols` / 时间线 / 推送。
- 下线现有 `platform=ima` 大 V 抓取通道。
- 新建第三套 ima 抓取，或现场现拉列表、不落本地条目。
- 全文检索、问答、未读、收藏、推荐。
- 管理员手工改单篇标签，或为知识库另建一套词表。
- 单独的知识库广场或群组管理页。
- 每库单独的「立即同步」按钮。
- 封面图新代理通道。

## 2. 与已有规格的关系

三层叠加，不揉成一份：

| 层 | 规格 | 职责 |
|---|---|---|
| 归档 | 多群组文档中心 | `ImaGroupConfig`、自动发现、按库 PDF/TXT、群组筛选 API |
| 节奏 | 按群间隔 | `interval_seconds`、到期才采、去掉全局间隔 |
| 产品 | 本规格 | 入口改名、授权、订阅、元数据优先阅读 |

共用模型：一个 ima 订阅库 = 一行 `ImaGroupConfig`。`enabled` 和每库间隔只表示「采不采」。谁能看见、谁订了，只由本规格的 ACL 与订阅表决定。

不对任何人发权，用户就订不到（「藏库」）。要停采，用现有 `enabled`。不新增 `hidden` 字段。

实现顺序：先等多群组注册表（以及按群间隔，若同期在做）合入，再在这套模型上加产品层。不在当前单群 `main` 上另开并行实现，也不改隔壁正在动的采集循环。

## 3. 架构

继续只跑现有 ima 文档采集：UID / Refresh Token、发现已订阅库、按库拉列表、下 PDF、抽 TXT。本轮不改文件格式、不改下载。

在采集之上加产品层：

- 目录：自动发现的已订阅库（与多群组注册表对齐）。
- 权限：新库默认只有管理员能看、能订；管理员再点名授权。
- 订阅：被授权的用户自己勾选；没订的库不出现在「已订阅」。
- 阅读：列表标题 / 摘要 / 封面 / 标签；有 PDF 再打开。TXT 阅读与 PDF 预览/下载沿用现有实现。
- 打标：采集写入或回填时，用现有规则扫标题、摘要、已有 TXT；标签只存在知识库记录上，不写 `posts`。
- 隔离：不写 `posts`，调度器不为知识库推送。

采集是否跑某个库，和用户能不能看见分开。后台可以照常采；用户侧只认授权 + 订阅。

## 4. 数据与权限

### 沿用

- `ima_pure_groups` 中的 `id`、`name`、`knowledge_base_id`、`root_folder_id`、`enabled`、`source`，以及按群间隔规格的 `interval_seconds`。
- `ima_pure_group_sync_at`、manifest/state、`<day>/<name>.pdf|.txt`。
- 群组 `id` 与 ima 返回的稳定知识库标识对齐（自动发现项）；手动兜底项仍用多群组规格的稳定内部 id。

### 新增表

`ima_kb_acl`：

- 主键 `(group_id, user_id)`
- 含义：该用户可以订阅这个库
- 空表（该 `group_id` 没有任何行）= 只有管理员能看、能订

`ima_kb_subscriptions`：

- 主键 `(user_id, group_id)`
- `created_at`：unix 秒，NOT NULL
- 含义：该用户已经订阅这个库
- 授权不等于自动订阅

不把知识库写入 `kols`，不复用 `kol_acl` / `subscriptions`。

### 读写规则

- 管理员：可看全部已注册库（含未授权、未订阅），可订，可管 ACL 与采集。管理访问不依赖自己是否订阅。
- 普通用户「可订阅」：`ima_kb_acl` 有自己，且尚未订阅。
- 普通用户「已订阅」：ACL 仍有效且订阅表有自己。
- 普通用户读条目 / TXT / PDF：必须同时满足 ACL + 订阅。任一不满足，按「不存在」处理（404），不用 403 暴露库还在。
- 管理员撤权：立即删除该用户对该库的订阅行；之后读条目 404，「已订阅」里消失。
- 新发现的库：不插入任何 ACL 行。
- 用户不能订阅不在 ACL 中的库（404）。

### 条目元数据

manifest / 列表记录在现有字段上增加（有则写，无则空）：

- `abstract`：列表接口返回的摘要（`abstract` 或 `introduction`）
- `cover_url`：列表接口返回的公开封面。只存接口里已经带的 URL，不新开下载通道；前端加载失败则不显示图
- `tags`：字符串数组，自动打标结果。不写进 `posts.tags`

不改 `media_id`、`name`、`day`、`size`、`md5`、PDF/TXT 路径。旧记录没有摘要/封面时，列表只显示标题；没有标签则不显示标签条。

## 4.1 自动打标

复用现有 `app/tagging.py` 与后台「标签分类」里的词表、常用股票名表、别名表。不另建知识库词表。要标某行业，管理员在现有词表里加该行业标签和关键词即可。

输入文本（按顺序拼成一段再匹配）：

1. 标题（`name`）
2. 摘要（`abstract`）
3. 若已有 TXT，追加全文。研报往往没有雪球 `$股票名(代码)$` 标记，股票主要靠常用股票名表子串命中；若正文里偶尔带该标记，现有提取规则照常生效。

规则与上限与动态贴文一致：话题/行业标签最多 3 个（词表顺序），股票标签最多 2 个，总上限 5，无命中则空数组。纯本地关键词，不走 LLM。

何时打标：

- 新条目在采集完成（manifest/state 写入、TXT 若已生成）后打一次，写入该条 `tags`。
- 存量已归档条目上线时回填一次。
- 后台词表或股票名表变更后，跟随现有「回填未打标 / 标签维护」路径，用同一套有效标签集合清知识库里的过期标签并按需重算。不单独发明每日任务。

不提供单篇手工改标。标签不写入 `posts`，时间线筛选看不到知识库条目。

## 5. 用户与管理流程

### 用户

侧栏「IMA 文档」改为「知识库」。时间线横幅同步改文案，仍跳知识库入口，不把条目打进动态流。

知识库页两个页签，不另开广场：

1. **已订阅**：自己订了的库。点进一个库看该库条目。在此退订。
2. **可订阅**：已被授权、尚未订阅的库。只能订，不能读条目。

条目列表：标题、摘要、封面、标签；日期分组可作为库内二级结构（多群组规格已有），不再作为模块主定位。搜索默认在当前打开的库内，匹配标题与摘要。若在知识库首页搜索，只覆盖已订阅库，结果带库名。库内可用标签筛选（股票名或行业/话题标签），选项来自该用户在该库已有条目上出现过的标签，不另开全站标签广场。

阅读页：先展示标题 / 摘要 / 封面。本地已有 TXT 则沿用现有文本视图；已有 PDF 则保留「查看 PDF」和下载。两者都没有时，不提供会失败的打开按钮。

### 管理员

仍在后台现有 IMA 采集配置区的群组行上操作。间隔、启停采集归隔壁规格。本轮每行只加「授权用户」（逗号分隔用户名，交互对齐私有大 V 白名单）。空 = 只有管理员能看 / 订。

发现的新库自动出现在这张表，默认空授权。不另开群组管理页。

### 路由

- 前端路由改为 `knowledge`。旧 `ima-documents`（及文档深链）重定向到对应知识库路由，查询参数 `group` / `q` / `day` 尽量保留。
- HTTP API 路径保持 `/api/ima-documents*`，避免和正在改多群组的实现抢路由。

## 6. 界面

- 侧栏、页面标题、空态、时间线入口：一律称「知识库」，不再称「IMA 文档」「已归档研报 PDF」。
- 知识库首页：页签 + 库卡片（库名、条目数；有 PDF 的库可有一句「有 PDF 可打开」）。
- 库内列表：卡片或行展示标题、摘要截断、封面（可无）、标签、日期、大小；跨库结果才标库名（若首页已先选库，则不重复标）。
- 库内筛选：标签下拉或 chip，与时间线「按标签筛选」同形态，但不写入时间线状态。
- 后台群组行：现有名称 / 路径 / 启用 / 间隔之后，追加授权用户输入。词表和股票名表仍在「标签分类」，知识库不另开词表页。
- 样式只扩展现有 IMA 文档与后台表单，不新开视觉体系。移动端控件保持 44px 触控。

「全部群组」不再对普通用户开放跨库通看。用户先选自己订了的库。管理员在后台仍按库管理；若管理端需要预览，走管理员身份的知识库页（能看到全部库），不把「全部群组」做成普通用户默认视图。

## 7. API

现有列表 / 详情 / TXT / PDF 接口：

- 继续登录才能访问。
- 按上面的读写规则过滤。普通用户传了未订阅或未授权的 `group` → 404。
- 条目列表接口不承担「可订阅」目录；两个页签由库目录接口区分。
- 条目 JSON 增加 `abstract`、`cover_url`（可空）、`tags`（可空数组）。不返回 token、cookie、签名下载 URL、本地绝对路径。
- 条目列表增加可选 `tag` 查询参数，只返回带该标签且当前用户有权看的条目。

新增（均挂在现有 ima-documents 前缀下，具体路径实现时保持一组、不平行发明第二套）：

- `GET` 当前用户的库目录：区分已订阅 / 可订阅。
- `POST` / `DELETE` 订阅、退订。
- 管理员 `PUT` 某库 ACL（用户 id 或用户名列表，与现有私有大 V 白名单一致）。
- 管理员读 ACL 可附在 `GET /api/admin/ima-collector` 的 `groups[]` 上，例如 `acl_usernames`，避免多打一枪。

公开响应继续脱敏。写 ACL / 订阅记审计日志。

## 8. 失败与空态

采集与发现失败沿用多群组 / 按群间隔规格：发现失败不清空注册表；单库同步失败不阻塞其他库。

本规格补充：

| 情况 | 表现 |
|---|---|
| 普通用户未被任何库授权 | 「可订阅」为空，不提示任何库名 |
| 已授权未订阅 | 「可订阅」可见该库；条目 / TXT / PDF API 一律 404 |
| 撤权 | 「已订阅」消失；旧深链 404 |
| 条目无 PDF / 无 TXT | 只展示元数据，不提供坏掉的打开/下载 |
| 封面 URL 失效 | 不显示图，不影响阅读 |
| 账号凭证失效 | 仅管理员状态区提示；权限仍有效的用户可继续读已归档内容 |
| 未配置采集 | 管理员看到配置引导；普通用户看到空知识库，不出现误导性文档堆 |

## 9. 组件边界

- `ImaGroupConfig` / 采集 / `_sync_group` / 间隔：本轮不改语义，只在拉列表写入摘要/封面、采集完成后调用打标时做最小扩展。
- `ImaDocumentStore.documents` / `document`：接受「当前用户可见的 group_id 集合」和可选 `tag`，绝不靠前端过滤。
- 打标：抽一层「对任意 title+body 跑现有规则」的调用，供采集和回填使用；不把知识库条目改造成 `Post`。
- 新模块（或 `ima_documents` 旁的小组件）：ACL 与订阅的读写、撤权级联。
- 文档 API：鉴权过滤 + 目录/订阅接口 + `tag` 筛选。
- `app/static/app.js`：导航改名、`knowledge` 路由与重定向、已订阅/可订阅、库内元数据列表与标签筛选、后台授权输入。
- 调度器与 `posts`：不接入。标签维护若已有入口，顺带处理知识库 `tags`，不新增独立调度。
- 时间线：只改入口文案和跳转，不插入知识库条目。

## 10. 验证标准

- 新发现库：管理员能在采集表看到；普通用户「可订阅」「已订阅」都为空，且猜 id 也 404。
- 授权用户 A 之后：A 在「可订阅」看到该库，未订时读条目 404；用户 B 仍完全不可见。
- A 订阅后：能列条目、读已有 TXT/PDF；退订后不能读。
- 撤 A 的权：订阅行删除，A 立即 404。
- 列表有摘要/封面的新记录能返回这两个字段；旧记录缺字段时只显示标题。
- 标题/摘要/TXT 命中词表或股票名时写入 `tags`；无命中为空。按 `tag` 筛选只返回有权且带该标签的条目。
- 词表变更后的过期标签清理覆盖知识库记录，且不把这些标签写进 `posts`。
- 无 PDF 的条目不出现可用的 PDF 按钮；有 PDF 的条目打开/下载行为与现网一致。
- 侧栏与时间线入口称「知识库」；`#ima-documents` 深链能进入对应知识库页。
- `enabled`、每库间隔、PDF/TXT 路径和下载不被本轮改坏。
- 同步知识库不写入 `posts`，时间线/推送没有新的 ima 文档卡片。
- 现有认证、路径安全、token 脱敏测试继续通过。

## 11. 实现顺序

1. 确认多群组注册表与按群 `group` 筛选 API 已合入（或与 Pi 的分支对齐后再改产品层）。
2. 表 `ima_kb_acl` / `ima_kb_subscriptions` + 服务端过滤；先让现有「全员可读」变成「默认仅管理员」。
3. 管理员授权输入；用户订阅/退订与两个页签。
4. 入口改名、路由重定向、时间线文案。
5. 列表/阅读元数据（摘要、封面）；无文件时的阅读空态。
6. 自动打标、存量回填、库内按标签筛选。
7. 回归采集、间隔、路径安全、贴文打标不被带偏。
