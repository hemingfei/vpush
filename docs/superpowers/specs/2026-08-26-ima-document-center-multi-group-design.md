# IMA 多群组文档中心设计

- 日期：2026-08-26
- 状态：待用户复核
- 目标：让同一 IMA 账号下的多个独立群组可被快速切换、筛选和阅读；保持 V Push “值班台”式的高密度、直接和手机可用。

## 1. 目标与范围

### 目标

1. 用户进入 IMA 文档页后，能在一个控件内切换群组，不必把不同群组混在一个无来源的日期列表里。
2. 用户可以查看全部群组并跨群搜索；结果明确显示来源群组。
3. 打开文档、返回列表、刷新页面后，仍保留当前群组和筛选上下文。
4. IMA 自动发现群组失败时，已有的手动配置仍可继续采集和浏览；单个群组失败不阻塞其他群组。
5. 兼容当前单群组配置和已经归档的文档，不要求重新下载历史文件。

### 范围

- IMA 群组注册表与自动发现/手动兜底。
- 采集配置、manifest/state、文档 API 的最小扩展。
- IMA 文档列表、群组切换、跨群搜索、日期筛选、阅读返回上下文。
- 后端和前端回归测试。

### 不在首期

- 左侧常驻群组导航。
- 桌面双栏阅读工作台。
- 未读、收藏、推荐、标签和阅读历史等需要新业务事实的状态。
- 单独的群组管理页面；先扩展已有后台「抓取设置」中的 IMA 配置区。

## 2. 交互方向：B+

### 页面结构

IMA 文档页保持单一内容列：

1. 顶部标题区显示「IMA 文档」、当前群组文档数和刷新操作。
2. 标题下放群组选择器，首项固定为「全部群组」。
3. 搜索框和日期筛选保持现有能力。
4. 文档仍按日期分组，日期标题显示该日期的文档数。

群组不超过 5 个时，桌面端使用紧凑分段切换；超过 5 个时改为原生下拉菜单，避免横向溢出。移动端始终使用原生下拉菜单，控件高度至少 44px。

### 切换行为

- 切换群组只替换文档区域，显示骨架加载，不重建整个页面。
- 切换群组清除日期筛选，保留搜索词。
- 「全部群组」对所有启用且有归档数据的群组搜索；每条结果显示群组名称。
- 具体群组视图隐藏重复的群组名称，优先保留文档标题、日期、文件大小和文本字数。
- 选择结果写入 URL 查询参数；刷新、浏览器前进/后退和打开文档返回时恢复选择。
- 群组列表和文档列表分别处理加载、空结果和错误状态。

### 阅读行为

- 阅读页标题下显示「群组 · 日期」上下文。
- 返回文档列表时恢复群组、搜索词和日期上下文。
- TXT 仍是默认阅读视图；PDF 继续按需展开，下载行为保持不变。
- 手机保持单列阅读；桌面不强制双栏。

## 3. 数据与采集边界

### 全局配置

账号 UID、Refresh Token 和同步间隔继续是全局设置，现有设置键和管理员权限不变。

### 群组注册表

新增一个持久化群组集合，每项包含：

- `id`：稳定的内部群组标识。
- `name`：展示名称。
- `knowledge_base_id`：IMA 知识库标识。
- `root_folder_id`：该群组文档根目录标识。
- `enabled`：是否参与同步和前台展示。
- `source`：`discovered` 或 `manual`。

自动发现成功后，以 IMA 返回的稳定群组标识合并注册表，更新名称和可用的路径信息；不会删除手动配置的群组。自动发现失败时保留现有注册表，并在管理员状态中显示发现失败原因。

如果 IMA 当前不能提供可用的订阅群组发现接口，手动行编辑作为正式兜底，不改变前端的群组模型。

### 兼容旧配置

当群组集合为空时，把现有的 `ima_pure_knowledge_base_id` 和 `ima_pure_root_folder_id` 视为一个手动群组。旧 manifest 中没有群组字段的记录归入这个兼容群组，历史 PDF/TXT 不迁移路径、不重新下载。

### Manifest 与 API

每条新 manifest 记录增加：

- `group_id`
- `group_name`
- 现有 `media_id`、`name`、`day`、`size`、`md5`、`ts` 保持不变

`GET /api/ima-documents` 增加可选 `group` 查询参数，响应继续保留 `items`，并增加群组摘要：

```json
{
  "groups": [{"id": "...", "name": "...", "count": 12}],
  "items": [{"media_id": "...", "group_id": "...", "group_name": "...", "name": "...", "day": "..."}]
}
```

现有只读取 `items` 的客户端保持兼容。所有公开响应继续不包含 Refresh Token、Cookie、签名 URL 或本地绝对路径。

### 同步

一次定时同步先刷新群组注册表，再逐个处理启用群组。每个群组使用自己的知识库/根目录参数，共享账号凭证和同步锁。结果记录成功群组数、失败群组数和失败群组名称；一个群组失败不能中止其他群组。

## 4. 组件与实现边界

- `ImaDocumentConfig`：保留全局设置，增加群组注册表的读取与兼容转换。
- `ImaPureClient`：接受单个群组上下文，复用现有加密请求、分页、下载和 PDF/TXT 转换逻辑。
- `ImaDocumentStore`：读写带群组元数据的 manifest，旧记录按兼容群组读取。
- `ImaDocumentService`：负责自动发现、逐群同步和聚合状态，不改变现有调度入口。
- 文档 API：增加群组摘要和群组筛选，不新增公开鉴权模型。
- `app/static/app.js`：新增当前群组状态、群组选择器、URL 上下文恢复和列表来源标识。
- `app/static/style.css`：只扩展现有 IMA 文档样式，遵循灰底白面、1px 描边、克制蓝和 44px 触控尺寸。
- 管理后台：在现有 IMA 文档采集配置区增加可重复群组行，支持启用/停用、编辑显示名和路径信息。

## 5. 状态、错误与权限

- 普通已认证用户：可读取全部已启用群组的归档文档。
- 管理员：可查看自动发现和逐群同步状态，编辑群组配置并触发同步。
- 群组发现失败：不清空已有群组；后台显示错误与重试入口。
- 单群组同步失败：其他群组继续；前台已有归档保持可读。
- 群组无文档：显示“该群组暂未归档文档”。
- 全部群组无匹配：显示“没有匹配文档”。
- 未配置任何群组：显示配置引导，不显示误导性的空数据。
- API 继续使用现有认证和服务器端路径解析，媒体 ID 校验规则不变。

## 6. 验证标准

### 后端

- 自动发现结果能与手动群组合并，且不会删除手动项。
- 自动发现失败仍保留可用的手动群组。
- 旧单群组设置和旧 manifest 可读，且不触发重新下载。
- 多群同步中一个群组失败时，其他群组仍能完成；聚合状态准确。
- API 能按群组筛选，全部群组结果带来源，旧 `items` 客户端兼容。
- 认证、路径安全、秘密信息脱敏回归测试保持通过。

### 前端

- 群组选择器包含「全部群组」和可用群组。
- 切换群组只刷新列表区域，并正确处理骨架、空态和错误态。
- 全部群组结果显示来源；具体群组结果不重复显示来源。
- URL、刷新、返回列表能恢复群组和搜索上下文。
- 移动端选择器与按钮达到 44px 触控尺寸，长群组名不溢出。
- 资源版本递增，静态 JS 语法、前端交互和全量测试通过。

## 7. 设计取舍

首期选择 B+ 而不是 A/C，是因为当前核心问题是“在多个群组之间快速切换”，不是建立新的内容工作台。群组注册表把自动发现和手动配置隔离，既能适应 IMA 接口变化，也不把用户锁死在当前单群组设置上；如果未来群组数量明显增长，再将同一注册表接入左侧导航，而不需要重做归档和 API。
