# 管理员手册

## 一、部署

### 方式 A：Unraid（推荐）

安装 Docker Compose Manager 插件后，添加项目 `/mnt/user/appdata/dav-subscription/docker-compose.unraid.yml`，或在社区应用市场安装 vpush 模板。首次启动填好：

- `WEB_ADMIN_PASSWORD`：创建 admin 账号的密码（必填）
- `FEISHU_APP_ID/SECRET`、`TELEGRAM_BOT_TOKEN`：推送渠道
- `XUEQIU_COOKIE`：雪球 Cookie（**必需**，无/失效 cookie 抓取接口返回 400；失效时后台「数据源 → Cookie 管理」粘贴新串即可，不用重启）

启动后访问 `http://<Unraid IP>:18084`，用 `admin` + 设置的密码登录。

### 方式 B：Docker Hub 镜像

```bash
docker run -d --name vpush \
  -p 18084:8000 \
  -v /path/to/data:/data \
  -e WEB_ADMIN_PASSWORD=你的密码 \
  -e TELEGRAM_BOT_TOKEN=你的token \
  -e FEISHU_APP_ID=... \
  -e FEISHU_APP_SECRET=... \
  YOUR_DOCKERHUB_USER/vpush:latest
```

数据保存在挂载目录的 `dav.db`，定期备份该文件即可（`python3 scripts/backup.py data/dav.db backups 14`）。

## 二、日常管理

### 大V管理

- 「大V管理」：添加/编辑/停用/删除大V，支持雪球主页链接自动提取 UID；标记「优先」的大V每 60 秒抓取一次，其余 180 秒。
- 「批量导入」：一次粘贴多行「昵称 + 雪球主页链接/UID」，快速建目录。
- 「分类管理」：给大V分类，推送卡片和广场都会显示分类。

### 系统 KOL Webhook（外部程序代替 KOL 发言）

每个**系统 KOL**（平台为「系统」，如「AI 分析报告」）都可以开启一个专属入站 Webhook：外部程序向该地址 POST 消息，系统就会以这个 KOL 的名义发帖，并按订阅关系实时推送给订阅者（走正常推送链路：免打扰、次要合并、推送重试等均生效）。

- **开启方式**：管理后台「大V管理」，系统 KOL 行点「Webhook」→ 勾选「启用 Webhook」→ 复制生成的地址。仅系统 KOL 支持；重新生成 Token 可让旧地址立即失效（泄露后轮换用）。
- **请求格式**（兼容飞书自定义机器人）：
  - 飞书文本：`{"msg_type": "text", "content": {"text": "大家好"}}`
  - 飞书富文本：`{"msg_type": "post", "content": {"post": {"zh_cn": {"title": "标题", "content": [[{"tag": "text", "text": "第一行"}]]}}}}`（取文本与链接）
  - 简化格式：`{"text": "正文", "title": "可选标题", "images": ["https://…/a.png"]}`
  - 可选 `msg_id` 字段实现幂等：同一 msg_id 重试只发一条。
- **签名校验（可选）**：在弹窗里设置签名密钥后，请求必须带飞书同款 `timestamp` + `sign`（`sign = base64(hmac_sha256(key=f"{timestamp}\n{secret}"))`，时间戳偏差 1 小时内），否则返回 403。
- **限制**：每 token 每分钟 100 条（对齐飞书）；正文上限 8000 字符；返回体带 `code`/`msg`/`post_id`。
- curl 示例：
  ```bash
  curl -X POST 'https://你的域名/api/kol-webhook/<token>' \
    -H 'Content-Type: application/json' \
    -d '{"msg_type":"text","content":{"text":"大家好"}}'
  ```

### 用户管理

- 用户列表是账号台账：来源（邀请码 / Telegram / 飞书 / 微信 / 网页）、能否密码登录、最近登录。历史脏登录名会标记，不锁登录，在「管理」里改名。
- 「管理」按任务拆开：改名、设/重置密码、权限、测试推送、删除。机器人号会标明无密码、不能网页登录。
- 不能删除管理员（含别人）；删除确认会写出订阅数和已绑渠道。未激活清理规则收在列表底部：领码后从未登录、没绑渠道、没订阅的空号；页头能看见当前天数，缩天数若会删人会先确认。
- 管理员只能由后台指定；`WEB_ADMIN_PASSWORD` 只在首次启动创建 admin 时生效。

### 帖子与推送

- 「帖子」：按关键词/平台搜索历史帖子。
- 「推送记录」：按用户/渠道/状态筛选，排查推送失败原因。
- 抓取失败（微博登录、雪球 cookie、用户推送失败）会自动向管理员渠道告警，每小时最多一条。
- **每日精选**：配置了 `LLM_API_KEY` 时，每日精选由 LLM 梳理成一条精炼综述发送——一句总览 + 最多 3 条纯文本要点（每条 60~80 字，按重要性/话题归并，不带原文链接）；未配置或综述失败时降级为原始贴文列表。免打扰汇总与合并摘要保持原样。

### 贴文标签（关键词规则自动打标）

- 新帖抓取入库时，系统按**关键词规则**自动打标（纯本地计算，零成本、不依赖 LLM）：标题/正文命中任一关键词即打该标签，每条最多 3 个话题标签；无命中则不打标。
- **股票标签**：帖子含雪球 `$股票名(代码)$` 标记（如 `$中船特气(SH688146)$`）会自动打上股票名标签；纯文字提及（如「长鑫」）命中「常用股票名」表也会打标。每条最多 2 个股票标签，与话题标签并存（总上限 5）。
- **黑话别名自动识别**（需配置 `LLM_API_KEY`）：系统每日一次扫描帖子，用 LLM 识别股票昵称（如「宁王」→「宁德时代」），高置信度自动写入别名表，打标即时生效。未配置 LLM 时跳过识别。每次仅几百 token，成本可忽略。
- **股票名/别名自动扩充**（需配置 `LLM_API_KEY`）：每日任务会扫描帖子里的雪球 `$股票名(代码)$` 标记，用 LLM 区分正式名与戏称/简称（如 `$涂改液(SZ000858)$` → 五粮液）——新官方名自动进股票名表、新戏称进别名表，名表/别名表各上限 200 防膨胀。
- **历史误标自动清理**：每日随别名任务一起，删除不在当前词表/股票/别名集合里的过期标签（如旧版词表的「观点/策略/生活」残留）。
- 「标签管理」页可：
  - 编辑词表（**每行一个标签，格式「标签名 | 关键词1,关键词2」**，最多 30 个标签；关键词决定命中效果，建议保持精简、用不易歧义的核心词）；
  - 编辑**常用股票名表**（每行一个股票名，用于纯文字提及识别）；
  - 编辑**黑话别名表**（每行「别名=正式名」，LLM 自动识别的在此可见可改）；
  - 查看已打标/待打标数量；
  - **LLM 标签维护**：立即扫描帖子识别别名/$标记$ 新股、去掉指数误入的股票名、清理过期标签；可接着回填待打标或重算全部（不用再找人跑脚本）；
  - **回填全部未打标贴文**：按当前词表 + 股票名单 + 别名给存量贴文补标签。
- 用户端「最新动态」页筛选面板可选择标签查看（含股票标签），贴文卡片上会显示标签。
- 话题与股票打标是纯本地规则（零 token）；仅每日一次的黑话识别用到 LLM。

### 运行状态

「状态」页可看轮询间隔、最近抓取时间/耗时、大V/用户/帖子数量。轮询异常会在页面显示。

## 三、配置项

| 环境变量 | 说明 |
| --- | --- |
| `WEB_ADMIN_PASSWORD` | 首次启动创建 admin 账号的密码 |
| `WEB_ALLOW_REGISTER` | 是否开放网页注册（默认 true） |
| `WEB_TOKEN_SECRET` | 登录 token 密钥（留空自动生成并持久化） |
| `FEISHU_APP_ID/SECRET` | 飞书自建应用凭据（机器人订阅 + 按人推送） |
| `FEISHU_CREDENTIAL_KEY` | 可选：飞书个人机器人凭据加密密钥（Fernet Base64）。也用于加密飞书文档 OAuth token。配置后用户在网页可扫码创建属于自己的飞书机器人，推送配额独立于共享应用。生成：`python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`。只读环境变量、不落库；更换密钥后用户需重新绑定个人机器人，飞书文档需重新授权。 |
| `FEISHU_DOCS_APP_ID/SECRET` | 可选：飞书云文档应用凭据，与消息推送应用分开。配齐后可在「研报库设置 → 飞书文档」授权并添加 Wiki/Docx 来源。添加后的飞书组对所有登录用户可见，不必再配 ACL |
| `FEISHU_DOCS_REDIRECT_URI` | 飞书文档 OAuth 回调，须与开放平台一致，形如 `https://your.domain.com/api/admin/feishu-documents/oauth/callback` |
| `FEISHU_DOCS_SCOPES` | 须与该应用已开通权限一致。默认 `wiki:node:read docx:document:readonly docs:document.media:download offline_access` |
| `FEISHU_DOCS_INTERVAL_SECONDS` | 飞书文档增量检查间隔，默认 60，最小 15 |
| `WECOM_WEBHOOK_URL` | 企业微信群机器人 webhook（系统级告警/启动通知；用户可在网页自行绑定各自的群机器人） |
| `VAPID_PRIVATE_KEY` / `VAPID_PUBLIC_KEY` | 可选：浏览器 Web Push 密钥。留空则首次有用户打开推送设置时自动生成并写入数据库 |
| `VAPID_MAILTO` | 可选：VAPID 联系邮箱，默认 `mailto:admin@localhost` |
| `TELEGRAM_BOT_TOKEN` | Telegram Bot token |
| `TELEGRAM_CHAT_ID` | 全局推送会话 ID（管理员告警/启动通知） |
| `TELEGRAM_PROXY` | 可选：Telegram API 代理，如 `http://127.0.0.1:7890` |
| `TELEGRAM_RICH_MESSAGES` | 可选：Telegram Rich Message 默认值（默认 true）。置 `0`/`false` 时全部退回 sendMessage + HTML。生产 / Unraid compose 已透传。管理员也可在「数据源 → 抓取设置 → Telegram 推送」勾选，保存后即时生效并优先于该环境变量 |
| `XUEQIU_COOKIE` | 雪球 Cookie（必需；失效时到「数据源 → Cookie 管理」粘贴，即时生效） |
| `TWITTER_COOKIE` | 可选：X Cookie 初始值；之后也可在「数据源 → Cookie 管理」覆盖，无需重启 |
| `WEIBO_USERNAME/PASSWORD` | 微博账号，配置后自动登录续期 |
| `LLM_API_KEY` | 可选：OpenAI 兼容接口密钥，配置后启用 LLM 摘要（免打扰/每日精选要点）与贴文自动打标 |
| `LLM_API_BASE` | LLM 接口地址，默认 `https://api.openai.com/v1`，可填 DeepSeek/本地 Ollama 等任意兼容服务 |
| `LLM_MODEL` | LLM 模型名，默认 `gpt-4o-mini` |
| `POLLING_INTERVAL_SECONDS` | 普通大V轮询间隔（默认 180） |
| `POLLING_PRIORITY_INTERVAL_SECONDS` | 优先大V轮询间隔（默认 60） |
| `POLLING_POSTS_RETENTION_DAYS` | 帖子/推送记录保留天数（默认 30，0 永久） |
| `DAV_UI_ONLY` | 置 1 时只提供网页 UI，不启动调度器/机器人长连接（本地调试用；防止测试实例抢生产 Telegram 机器人、误发告警） |
| `ALERTS_ENABLED` | 管理员告警总开关（默认 true）。置 false 时调度器照常抓取/推送订阅内容，但不发管理员告警（X 降级/数据源/推送失败/雪球 cookie 等）、不启动 TG/飞书 bot 长轮询——本地开发/测试实例用真实 config 启动时务必置 false，避免向生产群误发告警、抢生产 bot 轮询 |

## 四、飞书应用配置要点

- 机器人能力启用，权限含 `im:message:send_as_bot`、`im:message.p2p_msg:readonly`、`im:chat:readonly`。
- **可用范围**必须包含目标用户（部分成员/全体成员），否则单聊消息发送会被 230101 拦截。
- 用户在飞书里给机器人发过消息后，系统自动记录单聊会话，推送走 chat_id（比 open_id 稳定）。

### 个人机器人（可选）

共享应用整体约 1000 次/分钟限频；配置 `FEISHU_CREDENTIAL_KEY` 后，用户可在网页「推送设置」扫码创建个人机器人（飞书在其租户自动创建应用）。个人应用凭据加密存 `feishu_personal_bots` 表，绑定码存哈希；失效自动回退共享，解绑不影响共享字段。临时绑定监听按会话生命周期运行，不占常驻连接。

## 五、常见问题

- **改了权限/机器人能力没生效？** 需要创建新版本并发布，且经企业管理员审核。
- **Telegram 推送失败 SSL 错误？** 网络被墙，配置 `TELEGRAM_PROXY` 后重启。
- **Unraid 重启后服务没了？** 确认 compose 里 `restart: unless-stopped`。
- **X / 雪球抓不到、出口 IP 被墙或风控？** 到「数据源 → 代理」建池并按平台指定出口。池空或指定代理不可用时本轮抓取失败，**不会偷偷直连**（避免漏真实 IP）。

## 六、抓取代理

后台「数据源 → 代理」管理抓取出口（与 `TELEGRAM_PROXY` 无关，推送仍走自己的环境变量）。

- **按平台分配**：雪球 / 雪球组合 / 微博 / X 各自可选直连、指定池、指定代理。组合与雪球常同出口，但不强制绑定。
- **导入格式**（`#` 与空行忽略；无 scheme 时用池的协议）：
  - `host:port`
  - `host:port:user:pass`
  - `user:pass@host:port`
  - `host:port@user:pass`
  - `http://user:pass@host:port`
  - `socks5://user:pass@host:port`
- **提取池**：填商家提取 URL（http/https）。响应可以是纯文本一行一个，或 JSON 字符串列表 / `{data: [...]}` / `{ip,port}` 对象。按「过期秒数」写入节点，按「刷新秒数」定时再拉。提取请求本身不走代理。
- **旋转网关**：导入一条永不过期的 HTTP/S5，把该平台设为「指定代理」即可。
- 连续 3 次传输失败标失效；401/403 视为 Cookie/风控，不记代理死亡。管理员「测试」只探测，不改路由。
