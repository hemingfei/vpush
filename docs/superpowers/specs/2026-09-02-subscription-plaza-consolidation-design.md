# 订阅管理收敛到订阅广场设计

日期：2026-09-02
状态：已确认

## 目标

删除网页设置页中与订阅广场重复的“订阅管理”，把订阅发现与日常管理统一放在“订阅广场”。设置页只保留推送、渠道、AI 摘要和账号配置。

本设计取代 `2026-09-01-subscription-push-merge-design.md` 中新增“订阅管理”标签并设为默认页的决策；该文档其余已落地的统一订阅模型、组合入口收敛和旧路由兼容继续有效。

## 已确认决策

- 设置页删除“订阅管理”标签及其已订阅列表。
- 订阅广场新增“已订阅”和“特别关注”筛选，保留原管理页的主要查找能力。
- 网页导航与页面标题由“订阅与推送”改为“设置”。
- `/settings` 默认打开“推送设置”。
- 旧 `/mysubs` 路径进入订阅广场，并自动启用“已订阅”筛选。
- 后端订阅模型和 API 不变；`GET /api/my/subscriptions` 继续供“动态图片”设置使用。
- 小程序、Telegram 和飞书中的“我的订阅”不在本次范围内。

## 信息架构

网页顶层入口调整为：

1. **订阅广场**：发现全部大 V 和组合，也负责筛选、查看和维护已订阅项目。
2. **设置**：推送设置、渠道绑定、AI 摘要、账号设置。

设置页保留四个标签：

1. **推送设置**：默认打开；总开关、每日精选、X 翻译、免打扰、关键词和动态图片。
2. **渠道绑定**：渠道状态、接收渠道选择和绑定流程。
3. **AI 摘要**：用户自己的 OpenAI 兼容模型配置。
4. **账号设置**：密码与机器人账号同步。

## 订阅广场

广场继续使用 `GET /api/catalog`，不新增请求或后端字段。目录行已有 `subscribed` 和 `favorite`，前端在现有平台、分类和搜索筛选之后增加：

- **已订阅**：只显示 `subscribed === true` 的项目。
- **特别关注**：只显示 `favorite === true` 的项目。

两个筛选可组合，也可与平台、分类和搜索组合。清除筛选同时重置平台、分类、搜索、已订阅和特别关注。

桌面端把两个开关放入现有广场工具栏；手机端放入已有筛选面板，不增加新的顶层导航、弹窗或筛选页面。开关使用现有按钮样式，并提供 `aria-pressed` 状态。

订阅卡片继续保留订阅/退订、特别关注、次要订阅和雪球帖子/回复类型操作。操作成功后沿用当前路由感知刷新，不增加第二套列表状态。

## 删除范围

前端删除：

- 设置页 `subs` 标签和面板。
- 设置页订阅列表的加载、渲染、平台筛选及特别关注筛选逻辑。
- 只服务于该列表的状态、滑动平台切换分支和测试契约。
- 设置页渲染时用于订阅管理的重复加载请求。

保留：

- `GET /api/my/subscriptions` 及其 API 测试，因为“动态图片”设置仍依赖它。
- 订阅增删、类型、特别关注、次要和隐藏图片 API。
- `/combinations` 到广场组合筛选的兼容逻辑。

## 路由与状态

- `SETTINGS_TABS` 只包含 `push`、`bind`、`llm`、`account`；无效标签回退到 `push`。
- 离开设置页时，设置标签状态重置为 `push`。
- 访问 `/mysubs` 时先启用广场“已订阅”筛选，再用替换导航进入 `/home`，避免旧路径留在历史记录中。
- 旧路径只保证进入对应的新界面，不新增 URL 查询参数或持久化筛选协议。
- 访问普通 `/home` 时沿用当前会话内可见筛选状态；用户可通过“清除筛选”恢复全部目录。

## 错误与数据流

- 广场仍只有现有目录加载失败状态，不增加新的网络错误分支。
- 设置页不再为订阅卡片请求 `/api/my/subscriptions`；“动态图片”区域继续独立请求并独立显示加载、失败和重试状态。
- 订阅操作失败时继续沿用现有提示和服务端状态刷新。
- 快速切换路由时继续使用现有渲染序号，避免过期请求写入当前页面。
